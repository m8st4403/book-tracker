**v4.13.192**

ISBNで蔵書を登録し、発売予定・関連図書・おすすめをカレンダーで管理する本棚アプリのプロトタイプです。

## 現在のリリース

**v4.13.192**

## v4.13.192

今回の版では、過去に追加されてきた計測・回帰検査・診断・Mutationを棚卸しし、品質基盤を `QUALITY_CONTRACT.md` に統合しました。

また、シリーズ分類で作品名だけの書誌を出版シリーズscopeへ吸収した後に、ユーザーが選択した巻数順が壊れる問題を共通処理として修正しました。固定作品ではなく、scopeの位置・入力順を変えた合成データ24ケースで検証し、再ソート処理を意図的に壊すMutationも検出しています。検索結果についても発売日順・タイトル順・未登録優先を独立Oracleで検証し、検索ソートのMutation検出を追加しました。

登録計測については、API通信時間・ユーザー操作待ち・実データ処理・保存・画面更新を分離し、ユーザーが定価入力画面で待った時間をデータ処理性能として誤判定しない契約を維持しています。

## 品質基盤

- `SPEC.md`：アプリの機能仕様・不変条件
- `QUALITY_CONTRACT.md`：品質・横断監査・計測・Property・Mutation・E2Eの正本
- `DEV_GUARD.md`：開発ガードの説明
- `dev_guard.js`：静的・ロジック・Browser E2E・UI invariant
- `mutation_guard.js`：故障注入による検出能力の確認
- `RELEASE_TEST_GATE.md`：配布判定
- `ROADMAP_TEST_MATRIX.md`：未実装機能の先行契約
- `api_management.js`：Provider/Resolver基盤

## 開発・リリース

通常確認：

```bash
npm test
```

最終配布判定：

```bash
npm run test:release
```

`test:release` は品質テストに加えて、GitHubアップロードフォルダの内容、履歴資料の混入、バージョン整合性、必要な品質資産、ZIPの2階層構造を検査します。

## GitHubアップロードの運用

GitHubにアップロードするときは、**既存のGitHubアップロードフォルダの中身を削除してから、次のバージョンの `GitHubアップロード` フォルダ一式だけをアップロード**します。

`アップロード不要` は、CHANGELOG・過去監査・旧マトリクス・調査資料などの保管場所です。通常のGitHubアップロードには含めません。

現在のGitHubアップロード側には、現行版の実装と、それを検査するために必要なファイルだけを置きます。履歴資料を毎版コピーして累積させません。

## 重要な品質方針

新しい不具合が見つかった場合も、「不具合1件につきテスト1件」を追加することを第一選択にしません。

1. 共通不変条件として説明できるか
2. 独立Oracle/Propertyへ昇格できるか
3. Mutationで故障検出能力を確認できるか
4. 必要な代表E2Eだけを追加するか

の順に判断します。

これにより、過去の修正が継ぎ接ぎとして増殖することを防ぎます。
